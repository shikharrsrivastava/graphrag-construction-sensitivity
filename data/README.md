# Dataset provenance and local preparation

## Release-candidate data policy

The public release candidate is code-first and aggregate-results-only. It excludes raw HotpotQA questions and passages, context mappings, dataset-derived entity graphs and mappings, and extraction/embedding caches. Existing research files remain in the working repository on the maintainer's machine; they are excluded from the proposed Git index and are not deleted. The dataset manifests are retained as provenance records and contain counts and hashes, not question or passage text.

## Independently obtain HotpotQA

The experiments use `hotpotqa/hotpot_qa`, configuration `distractor`, split `validation`, through the Hugging Face `datasets` package. Review the current [dataset card and terms](https://huggingface.co/datasets/hotpotqa/hotpot_qa) before downloading or redistributing content. The card identifies CC BY-SA 4.0; HotpotQA passages are Wikipedia-derived, so confirm attribution, ShareAlike, underlying-source, and institutional requirements before publishing copies or derivative artifacts.

Install the Python dependencies from the repository root, then create a local sample in a directory that is not part of the release index:

```bash
python -m pip install -r requirements.txt
python -m src.load_data \
  --split validation \
  --limit 500 \
  --seed 2027 \
  --output-dir /path/to/local-data/pilot_500_v2
```

The loader streams and shuffles the upstream split, preserves per-question context passage IDs, deduplicates passage records, stores gold support labels for evaluation, and writes a manifest. The recorded canonical sample used `datasets` 5.1.0, shuffle buffer 10,000, 500 questions, and 4,947 passages. The manifest's expected question-ID and sorted-passage-ID SHA-256 values are `8440283bb8c1c0840680b57b580790555b9a341a3a54884027a14c0b5b42f810` and `e5fba7d953f5c5c1bd091741a6e7bc902d4b6e8eac1f9d2f973b6014c645b8db`. Compare a newly generated manifest against the retained reference values before treating it as the same sample. A seed alone does not guarantee byte-identical output if the upstream dataset or library behavior changes.

To run Stage A or Phase B, point `--data-dir` to the locally prepared directory. Stage A's secondary shared-global-graph track also expects the historical pooled graph and entity maps under `data/pilot_500/`; those are separate derived artifacts and are not generated by `src.load_data`. They can be built from a legally obtained passages file using `src.build_graph`, but reproducing the saved shared-graph comparison requires matching the original graph/mappings and extractor configuration. Phase B's primary graph construction is local to each question and does not use that pooled graph.

The presence of reproduction commands does not mean the complete experiments have been reproduced from a fresh download in a clean environment. See [the reproduction guide](../docs/reproduction_guide.md) for exact inputs, model requirements, and limits.

## Dataset directories retained locally

The repository's local research workspace contains these historical samples. Raw files are excluded from the release candidate:

| Directory | Role |
|---|---|
| `pilot_15/` | Early 15-question sample and pooled entity graph. |
| `pilot_50/` | Historical 50-question sample for pooled graph and stability experiments. |
| `pilot_500/` | Historical pooled 500-question sample and the graph/mappings used by early experiments and Stage A's secondary shared-global-graph track. |
| `processed/` | Legacy default path; files duplicate `pilot_15/`. |
| `pilot_500_v2/` | Canonical fixed input for Stage A and Phase B. |

The excluded local files include `questions.json`, `passages.json`, `question_contexts.json`, `entity_graph.graphml`, `entity_passages.json`, and `passage_entities.json` wherever present. Graphs and mappings are derived research artifacts, not gold knowledge graphs.
